# TCPGYT 测试与验收清单（Test & Acceptance v0.1）

**状态：草案（待审批）**
**关联：** `docs/01-prd.md`（§7 验收）、`docs/02-architecture.md`（§8）、`docs/04-api-contract.md`（§7）、`docs/05-data-model.md`（§4）、`docs/06-privacy-security.md`

> 本文件把 PRD/ADR 的验收标准转成**可复现**的测试用例:前置条件、步骤、期望结果、对应需求。
> 用例为契约级(与实现无关),Phase E 落地时映射为单元/集成/UI 测试。凡依赖未定实现的,标 **[待审批]**。

## 0. 用例编号约定

- `T-<域>-<序号>`;域:`DL`(下载)、`FILE`(文件)、`SET`(设置)、`SEC`(隐私安全)、`BRAND`(品牌捐赠)、`ARCH`(架构边界)。
- 每条含:前置 / 步骤 / 期望 / 覆盖需求(引用 PRD 验收号或 ADR §8)。

## 1. 下载与状态机

### T-DL-01 公开资源无 Cookie 全流程（PRD 验收 7、ADR §8-6）
- 前置:Cookie 关闭。
- 步骤:输入合法公开链接 → 解析 → 选格式 → 创建任务 → 等待完成。
- 期望:全流程 `credentialRef` 为空仍可完成;任务状态 QUEUED→DOWNLOADING→(POST_PROCESSING)→COMPLETED。

### T-DL-02 状态机合法转换与持久化恢复（PRD 验收 3、ADR §8-4）
- 前置:一个 DOWNLOADING 任务。
- 步骤:暂停 → 恢复 → 取消;并在下载中杀掉进程后重启应用。
- 期望:仅发生合法转换(05 §2.2);每次转换写 `StatusTransition`;重启后状态可恢复,不丢任务;`CANCELED` 不显示为完成。

### T-DL-03 失败归类与恢复建议（PRD 验收 4/5）
- 步骤:分别构造网络中断、存储写满、格式失效场景。
- 期望:得到对应 `FailureCode`(NETWORK/STORAGE_FULL/FORMAT_UNAVAILABLE) + 面向用户的恢复建议;`failureNote` 不含 URL 参数/凭据(06 §4)。

### T-DL-04 存储不足不产生假完成（PRD 验收 5）
- 步骤:在剩余空间不足时下载。
- 期望:任务进入 FAILED(STORAGE_FULL),不显示 COMPLETED;`totalBytes` 未知时不伪造(05 §2.1)。

### T-DL-05 后处理失败保留源文件（05 §2.2）
- 步骤:令 POST_PROCESSING(FFmpeg 合流)失败。
- 期望:保留已下载结果与失败原因,不静默删除文件。

## 2. 文件库

### T-FILE-01 筛选/搜索/排序
- 期望:全部/音频/视频筛选正确;搜索命中标题;排序在「最近添加↔名称」切换;空状态正确展示。

### T-FILE-02 文件操作四态区分（06 §6、章程 §5）
- 步骤:对一条已完成记录分别执行 打开文件 / 查看位置 / 移除记录 / 删除原型文件。
- 期望:移除记录只删 `DownloadTask`(+`StatusTransition`),不动媒体;删除媒体须**二次确认**后才删本体(04 §5)。

## 3. 设置与偏好

### T-SET-01 偏好持久化
- 步骤:改默认类型/清晰度/网络偏好/保存位置后重启。
- 期望:`AppPreferences` 持久且生效(05 §2.8);网络偏好默认值 **[待审批]**。

## 4. 隐私与安全（06 全文）

### T-SEC-01 Cookie 明文零泄漏（PRD 验收 9、ADR §8-2）
- 步骤:启用并导入 Cookie,执行一次需 Cookie 的下载,检查 Room 表 / SharedPreferences / logcat / 通知 / 分享内容 / 崩溃日志。
- 期望:任何位置均无 Cookie 明文;仅内存短暂持有,用后清(06 §1/§2)。

### T-SEC-02 Cookie 删除后不可再读（PRD 验收 9）
- 步骤:导入 → 使用 → `deleteOne`/`clearAll` → 再次尝试用同 `ref` 下载。
- 期望:引擎无法再取到该凭据。

### T-SEC-03 Keystore 降级不回退明文（ADR §5）
- 步骤:模拟 Keystore 无法安全初始化。
- 期望:Cookie 功能被禁用,绝不以明文回退存储。

### T-SEC-04 无远端调用（章程 §1、ADR §8-3）
- 步骤:全程抓包/审计网络。
- 期望:除目标资源本体与(可选)缩略图外,无指向本项目自有服务端的请求;无遥测/账号/同步(06 §5)。

### T-SEC-05 敏感 URL 不落库（05 §2.1、06 §1）
- 期望:`DownloadTask` 仅存脱敏 `sourceUrlDisplay`;原始 URL(含 token)、授权头不持久化。

## 5. 架构边界（ADR §8）

### T-ARCH-01 UI 不可直达引擎/自由命令（ADR §8-1/§8-8）
- 期望:不存在从 UI/ViewModel 直接执行下载命令或拼接 yt-dlp 原始参数的路径;下载全经 04 §1 适配层;无自由文本命令入口。

### T-ARCH-02 层可替换（ADR §8-5）
- 期望:引擎/持久化/文件/UI 经 04 接口隔离,替换实现不破坏其余层。

### T-ARCH-03 不引入未批准二进制（ADR §8-8、章程 §5）
- 期望:无 aria2c / 命令模板 / 二进制自更新逻辑。

## 6. 品牌与捐赠（PRD 验收 10/11）

### T-BRAND-01 捐赠未配置降级（验收 10）
- 步骤:清空 `support.donationUrl`。
- 期望:入口隐藏或显示不可点击「暂未开放」,**不出现失效链接**(08 待补)。

### T-BRAND-02 品牌可替换不改业务（验收 11）
- 步骤:替换 logo/appIcon/appName。
- 期望:下载/文件/设置业务逻辑不受影响;未配置时走安全占位。
